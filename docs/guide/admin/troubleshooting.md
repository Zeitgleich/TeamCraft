# Troubleshooting

Start with `GET /healthz` (liveness), `GET /readyz` (database) and the logs
(`[logging] format = "json"` for collectors). Logs never contain tokens, keys or message content.

## Symptoms

| Symptom                                            | Likely cause and fix                                                                                                                                                                                       |
|----------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Server does not start: unknown configuration key   | A key was renamed or misspelled. Compare with `teamcraft.example.toml`                                                                                                                                     |
| All logins fail with 401                           | `[oidc] issuer` differs from the token's `iss`, or `client_id` is not in `azp`/`aud`; clock skew above `leeway_secs`; the server cannot reach `<issuer>/.well-known/openid-configuration` (set `jwks_uri`) |
| "Your account has no access to TeamCraft"          | The user has none of the four client roles of `client_id`. Assign one; check `[oidc.roles]` names                                                                                                          |
| Role changes or disabled users take hours to apply | `[oidc.sync]` is off. Enable it and give the service account its realm-management roles                                                                                                                    |
| Sessions survive a Keycloak logout                 | Back-channel logout URL missing or unreachable from Keycloak                                                                                                                                               |
| Web client login loops                             | The server's origin is not a redirect URI / web origin of the OIDC client                                                                                                                                  |
| Key setup says the passphrase did not unlock keys  | Wrong passphrase, or the server was unreachable. There is no reset; see recovery                                                                                                                           |
| Users cannot see each other's new identity key     | `tc_identity_key` attribute or mapper missing; run `dev/verify-realm.py` against the realm                                                                                                                 |
| Attachments fail with 503                          | `[storage]` is missing or unreachable. The endpoint must be reachable by **clients** (presigned URLs)                                                                                                      |
| Downloads fail for single files                    | Bucket and database out of sync after a restore                                                                                                                                                            |
| Meetings endpoints answer 503                      | `[meetings]` missing; `guest_token_secret` needs 32+ bytes                                                                                                                                                 |
| No invitation e-mail                               | `[meetings.smtp]` missing or wrong `security`/port; no CalDAV does not stop mail                                                                                                                           |
| Guest link says "does not work"                    | Used already (one-time), expired (meeting end + `guest_grace_secs`), meeting cancelled, or the secret changed                                                                                              |
| Calls: join token fails with 503                   | `[calls]` missing                                                                                                                                                                                          |
| Calls: "invalid token" at the SFU                  | Public key or issuer mismatch between server and SFU; keys rotated in only one place                                                                                                                       |
| Calls start but nobody rings or sees a roster      | SFU has no `TEAMCRAFT_SFU_SERVER_URL`/`REGISTRATION_TOKEN`, or the token differs from the server's                                                                                                         |
| No media from behind a firewall                    | `4433/udp` blocked (QUIC)                                                                                                                                                                                  |
| Browser push never arrives                         | No `vapid_private_key`; web client not on HTTPS; browser subscribed with an old public key                                                                                                                 |
| Android gets no background push                    | FCM/UnifiedPush senders are stubs on the server (see [Push](push.md))                                                                                                                                      |
| 429 responses                                      | Rate limits (`[security.rate_limits]`); behind a proxy set `trust_forwarded_for` or all clients share one address                                                                                          |
| Gateway disconnects every hour                     | Expected: `connection_max_age_secs` forces a token re-check; clients resume                                                                                                                                |
| WebSocket drops through the proxy                  | Proxy buffers or times out upgrades on `/api/v1/gateway`                                                                                                                                                   |
| Bridge sends nothing                               | Bot not yet added to the channel **by a member** (messages wait, up to 1000)                                                                                                                               |
| Bridge returns 404 on a hook                       | Unknown source token                                                                                                                                                                                       |

## Known gaps between design and code

Where the design documents say more than the code does today (checked against `main` and the open v1 pull requests):

| Area                     | Design says                                                                                        | Code does                                                                                                         |
|--------------------------|----------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------|
| Recovery                 | Passkey (WebAuthn PRF) is the primary recovery (e2ee.md §6.2)                                      | Passphrase only; the passkey step is a placeholder in the UI                                                      |
| `admin_self_join`        | `owner_approval`: a channel owner approves                                                         | No approval flow; clients refuse the self-join                                                                    |
| Organization recovery    | Admin-started, two admins approve                                                                  | Core and server implement it; the console's *Start recovery* button is not wired                                  |
| Channel roles            | Signed per-channel roles                                                                           | Not in a signed log; any member can commit membership changes, the server's permission check is the finer control |
| Local accounts           | Guests with password and TOTP                                                                      | Works through the API and the login screen; the **activation page is missing** in the web app                     |
| E-mail digest            | A setting in the app                                                                               | API only (`/me/email-digest`)                                                                                     |
| Admin features           | Move channel between spaces, delete a channel, user groups UI, default spaces, templates, branding | No endpoints for moving, deleting, default spaces, templates, branding; groups are in the directory               |
| Storage usage            | Per space                                                                                          | Totals only (Instance page)                                                                                       |
| Audit export             | Exportable                                                                                         | JSON via API only; CSV export is a placeholder                                                                    |
| SFU nodes                | Registration, health, load in the admin UI                                                         | One SFU configured by environment; the Instance page shows last contact and running calls                         |
| Files                    | Attachments, previews, share links                                                                 | Works; revoking a share link is API only                                                                          |
| Search                   | Encrypted shared index                                                                             | Works; the browser keeps its index in memory for the session                                                      |
| Push                     | APNs, FCM, UnifiedPush                                                                             | Only Web Push delivers; the other senders are stubs (the Instance page says so)                                   |
| Calls                    | Browser and iOS calls, reactions, recording, captions                                              | Desktop and Android only; the rest is coming soon                                                                 |
| Meetings                 | Per-organizer calendars, recurring exceptions                                                      | One calendar account; recurrences are handled as a series                                                         |
| Telephony                | SIP trunk, AI hotline                                                                              | Design draft only                                                                                                 |
| Compliance archive       | Optional archive                                                                                   | Policy field accepts only `off`                                                                                   |
| `teamcraft.example.toml` | Documents every option                                                                             | Lacks the `[local_accounts]` section                                                                              |
